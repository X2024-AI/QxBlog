LingBot-VA — Deployment & Operations

How to serve, evaluate, and monitor the model — the exact commands and gotchas, so anyone (including future me) can reproduce it.

8×A100 · sm80 websocket + msgpack tmux-managed serving

1What LingBot-VA is

A video-action robot policy on the Wan2.1 video-diffusion stack (Wan 3D transformer over a VAE latent space, conditioned by a T5 text encoder). Served server–client over websocket + msgpack. All components derive from one config field wan22_pretrained_model_name_or_path (a dir holding transformer/, vae/, tokenizer/, text_encoder/).

2Hardware & environments

  • Host: 8× A100-80GB (sm80 — no FP8), shared with other users' jobs. Always nvidia-smi first.
  • Model env /data/envs/lingbot-va (torch 2.9.0+cu126, no flash-attn, SDPA).
  • Sim env conda robotwin; openpi env /data/qx_workspace/openpi (MuJoCo, MUJOCO_GL=egl).

3Serving a checkpoint (real robot)

Deploy dir pretrained/grasp_bottle_serve/: symlink vae/tokenizer/text_encoder to pretrained/lingbot-va-base, transformer to the checkpoint, and patch config.json attn_mode flex → torch (the only diff vs the raw ckpt).

Config va_grasp_bottle_serve_cfg.py: num_inference_steps=8, action_num_inference_steps=20, attn_window=36, RTC on. Registered as grasp_bottle_serve.

Launch in tmux (never from a tool call — nohup/setsid procs get reaped when the launching process group is cleaned):

tmux new-session -d -s lingbot_grasp -c /data/qx_workspace/lingbot-va \
  'CUDA_VISIBLE_DEVICES=0 TOKENIZERS_PARALLELISM=false \
   PYTORCH_CUDA_ALLOC_CONF="expandable_segments:True" \
   /data/envs/lingbot-va/bin/python -m torch.distributed.run --nproc_per_node 1 \
   --master_port 29062 wan_va/wan_va_server.py \
   --config-name grasp_bottle_serve --port 29537 --metrics-port 29538 \
   2>&1 | tee -a /tmp/lingbot_va_server_grasp.log'

Smoke-test protocol

  1. infer(dict(reset=True, prompt=...)) first (initializes frame_st_id).
  2. First chunk: obs as a single dict (cold-cache VAE temporal conv crashes on a list).
  3. infer(dict(obs=[8 keyframe dicts], compute_kv_cache=True, state=prev_action)).
  4. Step chunks with single-dict obs. Keys: observation.images.head (256×512) + wrists (256×256) + state (30,).

4RoboTwin-2.0 eval

bash evaluation/robotwin/launch_server.sh
task_name="adjust_bottle"; save_root="results/"
bash evaluation/robotwin/launch_client.sh ${save_root} ${task_name}
  • enable_offload=False — with True, one episode >1 h on 80 GB cards.
  • Client connects to 127.0.0.1, not 0.0.0.0 (proxy handshake failure).
  • curobo pinned v0.7.8; RoboTwin checkout c659e0d uses env_cfg/task_config/.
  • Vulkan/OIDN: pin server + client to the same idle GPU. Result: adjust_bottle 2/2.

5MuJoCo ground-truth replay

evaluation/openarm_mujoco/replay_gt.py replays recorded expert actions through the unchanged client. Key insight: success=False is often a harness artifact — grasp/release stages are event-driven (try_attach/prepare_release), so replaying joint targets alone never fires them.

6Monitoring panel

script/launch_panel.sh <gpu> <port> <metrics_port>, probes at 0.0003% overhead, JSON at /metrics. Remote access via SSH tunnel:

ssh -f -N -o ServerAliveInterval=30 -L 29599:127.0.0.1:29599 A100

7Server-stability post-mortems

  1. Process-group reaping — nohup & dies with the call's process group → setsid nohup.
  2. setsid still reaped on session end → tmux.
  3. tmux died once overnight + a drift warning (relaunch without --metrics-port → panel reads "offline").

Restart checklist: tmux session exists AND :29537/healthz 200 AND :29538/metrics alive AND nvidia-smi shows the model on the expected GPU.

8Host / GitHub quirks

  • Proxy: http://127.0.0.1:7890 (not [::1]). Push via URL-embedded PAT; http.version=HTTP/1.1 + postBuffer=52428800.
  • SSH: ssh.github.com:443 through the proxy.
  • Remote repo X2024-AI/lingbot_va_repro built via a graft commit (2824e01).
