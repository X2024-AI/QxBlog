The one-line takeaway

FP8 / TensorRT-LLM / FlashInfer were all wrong for this workload; the wins came from a nonzero sync, an accidental FSDP wrap, and hot-path empty_cache — things only a profile reveals. And "fast" isn't enough: bit-identical verification is what turns a speedup into a shippable result.

1Establish a real baseline

  • Streaming budget: 130 ms per robot tick.
  • One infer chunk = 25 video + 50 action denoise steps.
  • Baseline infer 10,278 ms (~79× over); compute_kv_cache 1,127 ms.
  • Methodology trap: a repeat-infer loop violates the streaming-VAE state machine — mirror reset → infer → compute_kv_cache → ….

2Profile to find where time goes

Decisive metric: GPU util 23.4% → CPU/launch-bound. Five hot spots:

  1. KV-slot pool syncs — torch.nonzero/any 2–3× per layer per step, ~1.4 ms CPU stall each → ~86 ms/step × 75 ≈ 6.5 s.
  2. Cache gather/scatter — ~1.2 s GPU + ~3.6 s CPU.
  3. fp64 RoPE + fp32 norms — ~30% of kernels are casts/norms.
  4. Hot-path waste — empty_cache() ×5, per-step clones, grid-id rebuild, 32k H2D.
  5. FSDP at world_size=1 (found during benchmarking) — ~4.3 s/chunk of allgather churn.

3Rank proposals against measurements

ProposalVerdictWhy
FP8✗No sm80 tensor cores; launch-bound, so bit-width isn't the constraint
TensorRT-LLM✗Targets AR decoders; this is a dual-stream video+action diffusion transformer
Paged KV (TileRT)△Right problem, wrong fix — a ring buffer kills the syncs with no new dependency
FlashInfer△Attention is only ~7.5% of GPU time; revisit later

4Implement in ranked order

  1. RingKVPool — contiguous ring buffer, host-side pointers, zero syncs → 10,278 → 7,342 ms (1.40×).
  2. Skip FSDP at world_size==1 — the biggest single win (~4.3 s/chunk).
  3. Hot-path cleanup — remove empty_cache, per-episode cfg_text_emb (150 clones/chunk), grid-id cache, log spam.
  4. RoPE kept fp64 — fp32 diverged the trajectory (corr 0.96 by chunk 2).

5Verify bit-identical

  • Digest-stream diff across 4,680 attention calls; 6-case equivalence suite.
  • My bug: transient key rebound before drop_last — silently zeroed the pool each step; unit tests missed it.
  • Legacy bug: transient slots freed by ascending id — frees a real entry, keeps stale garbage.
  • Chaos amplification: tiny FP reorder compounds through 75 flow-match ODE steps.
  • FSDP class rename (FSDPWanAttention) — post-wrap monkeypatches silently no-op.

6Benchmark honestly

Factors that skewed numbers: GPU squatters, two servers on one port, save_async pool writes, a forgotten CUDA_VISIBLE_DEVICES, and the in-process vs websocket-E2E gap (3.66 s vs 8 s) resolved by finding the FSDP path.

7Make it observable

  • Probes (0.0003% overhead) around 5 phases; --metrics-port inside the server process.
  • Panel: KPI row, stacked phases, trend vs 130 ms, phase-share advisory, before/after, multi-server.
  • Launch-bound signature: a neighbor job inflates all phases proportionally (3.8 → 8–9 s).
  • VAE encode = 85% of every kv-cache tick — the top remaining lever on the real-robot config.
